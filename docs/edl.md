# EDL reference

An EDL is a JSON file describing source videos, the ranges to retain and the graphics/audio anchored to them. Paths resolve relative to the EDL file, including overlay and music files. Every source must have video and audio tracks, and a unique filename stem, because transcript/audio caches use those stems. The `screen` source is required as the reference video and preferred microphone.

## Ranges and synchronization

```json
{
  "sources": {"screen": "screen.mp4", "camera": "camera.mp4"},
  "sync": {"camera": 5.9},
  "ranges": [
    {"source": "camera", "style": "cam", "start": 0, "end": 12},
    {"source": "screen", "style": "screen", "face": "camera", "start": 18, "end": 45}
  ]
}
```

`sync.camera = 5.9` means **screen time = camera time + 5.9**. Camera ranges use camera timestamps; screen ranges use screen timestamps. A PiP screen range seeks the camera at `screen_start - offset`. Verify synchronization near both ends of a long take; the helper reports offsets/drift evidence and writes `sync-proposal.json`, without changing your editable EDL.

Styles: `cam` is full-frame camera with the original warm grade; `screen` is the framed screen layout, with optional bottom-left camera PiP; `broll` uses the original stronger grade. These looks are retained defaults, not automatic analysis of your footage. `face_crops` can map source keys to `[x, y, width, height]` in source pixels; otherwise PiP uses a centered crop. The measured GoPro microphone repair from the original sessions is disabled unless you set `VIDEO_GOPRO_REPAIR=1`; it was calibrated for those recordings.

A camera range with a known sync offset borrows the screen mic when its entire span fits within the screen recording. Other ranges use their own audio. `audio_key` is a transcript/cache filename stem, not an alternate microphone selector; the loader sets it automatically. Do not assign a different stem.

`start`/`end` are source seconds, with `end` exclusive. Choose valid times within the actual file. `cut_silence` defaults to true except for b-roll; `keep_silence` defaults to 0.16 seconds. `drops: [[start, end], ...]` removes specified source-time spans in addition to silence. Remove a whole unwanted range from the EDL rather than expressing it as one full-span drop. Inspect the omission findings in the terminal and listen to joins; transcript timing is an estimate.

`speed` accepts 0.5–2 for camera/b-roll. PiP/screen speed changes are rejected. Output clips round to 30 fps and keep matching 48 kHz audio sample counts. Use segment/output offsets for graphics on retimed ranges: `src` graphic anchors and zoom programs are intended for normal-speed ranges.

## Zooms and graphics

Screen ranges accept `zooms` such as:

```json
{"at": 25, "to": 1.3, "fx": 0.6, "fy": 0.5, "dur": 0.35, "hold": 1.5}
```

`at` is source time, `to` is the zoom scale, `fx`/`fy` identify the normalized focal point, and `dur`/`hold` control the ramp and dwell. This is scripted zoom, not mouse tracking.

Graphic families include `titles`, `chips`, `callouts`, `prompts`, `countdown`, and transparent video `overlays`. Two useful anchors are:

```json
{"seg": 1, "offset": 0.4, "dur": 2, "text": "NEXT STEP"}
{"seg": 1, "src": 25.2, "dur": 2, "text": "ON THIS WORD"}
```

`seg` is the zero-based EDL range index. `offset` is seconds into its edited output; `src` is a timestamp from that source transcript, mapped through removed pauses. Without `seg`, use an absolute final-output `at`. Segment-anchored durations are clipped at that segment's end. Use `titles` for `text` with optional `sub`, `chips` for brief labels, and an overlay's `file` for a rendered alpha MOV. Examples are in the synthetic demo and `graphics/cards.example.json`.

HyperFrames cards are rendered separately:

```bash
python toolkit.py graphics graphics/cards.example.json --output-dir workspaces/my-video/graphics
```

Then add an EDL `overlays` entry with `file`, `seg`, `offset` and `dur`. Alpha videos remain transparent through FFmpeg compositing; the built-in progress bar is enabled with `"progress_bar": true`. Captions burn last.

## Audio, captions and outputs

An explicit effect can use the same anchors:

```json
{"seg": 0, "offset": 0.2, "name": "pop", "gain_db": -25}
```

Place it in `sfx`. Core names are generated by `engine/sfx.py`; overlay/chip/countdown transitions also create automatic cues. Optional `music` entries use anchors plus `file`, `from` (seconds into the music) and `gain_db` (default −26). Music/effects mix inside the main build, followed by loudness normalization. The separate God music helper supports voice-dependent ducking and tape stops; its command is documented in `commands.md`. Supply music you have permission to use.

Local transcripts live at `<edit-dir>/transcripts/<source-stem>.json`. `master.srt` is the burned two-word uppercase caption track; `final.srt` is the readable verbatim sidecar. Both use the actual clip durations and selected microphone. The editor also generates waveform silence maps, packed phrases, assets and PCM intermediate MOVs, then prints omission and QC findings. Reruns reuse clips only when the source metadata and extraction settings match their cache receipts.

If you already have transcripts and silence maps, omit `--prepare`. To regenerate after replacing a source or changing transcription settings, use `--prepare`. A clean session directory is the easiest way to keep separate projects independent.
